# 문서 작성 스타일 (공통)

## 작성자: @skim

- 아래 조건을 만족하는 문어체를 사용한다. 지향점은 논문과 전문 서적의 문체이며, 가급적 한자어를 사용하여 짧은 문장으로도 논리와 격식을 갖출 수 있도록 한다.
  - 서술할 내용과 생략할 내용은 문서의 성격과 독자의 사전 지식을 기준으로 선정한다. 예를 들어, 재설계 계획서의 독자는 대상 프로젝트를 이미 알고 있으므로 프로젝트 소개를 서술하지 않는다.
  - 내용이 이미 다른 문장에서 언급되었거나 전문 용어를 사용한 경우와 같이, 생략은 내용을 자연스럽게 유추할 수 있는 상황에만 허용한다. 단, 이미 설명된 내용이라도 그 위치가 멀어 기억하기 어렵다면 생략해선 안된다. 만약 어느 것에도 해당하지 않는다면, 서술부에서 적절히 풀어 써야 한다.
  - 주어부와 서술부의 순서는 일반적인 사용례를 따른다. 예를 들어, 두 문장 "아버지가 방에 들어가신다."와 "방에 들어가신다 아버지가."는 서로 의미는 동일하지만, 후자의 주부·술부 순서는 일반적이지 않으므로 지양한다. 우리는 문예를 하는 것이 아니다.
  - 주어와 서술어의 호응을 항상 확인한다. 주어를 생략한 문장은 남은 서술어와 짝이 맞는지 확인하고, 주어를 밝힌 문장은 서술어가 주어의 실체와 맞는지 확인한다. 웹앱인 대상을 "화면이다"로 서술하는 것이 불일치의 예이다.
  - "~두 개다", "~가 먼저다"처럼 짧게 끊는 구어체 종결을 쓰지 않고, "~로 구성된다", "~을 우선한다"처럼 격식 있는 서술어로 맺는다. 절 제목도 본문과 같은 기준을 따르므로, "다음 한 걸음" 같은 직역 어투가 아니라 "향후 작업"처럼 한국어 문서의 관례대로 작명한다.
  - 여러 항목을 나열한 뒤 각각을 설명할 때는 나열한 순서를 지키고, 나열이 이미 전달한 정보(항목의 수 등)를 되풀이하지 않는다.
  - 내용을 생략하기 어려운, 의미가 포괄적인 어휘는 의사가 제대로 전달될 수 있도록 범위(scope)를 좁혀 기술한다.
  - 문장은 사실 사이의 관계를 기준으로 나눌지 이을지를 결정한다. 예를 들어, 관계가 있으면 "-하되", "-므로", "-지만"처럼 그 관계를 드러내는 어미로 잇고, 관계가 없으면 끊는다. 관계 있는 것을 마침표로 끊고 관계 없는 것을 쉼표로 붙여선 안 된다.
  - 직역체, 직역 어투의 낱말이나 어휘 사용을 지양하되, UX/UI처럼 대중적으로 사용되는 전문 용어는 오히려 사용하는 것을 권장한다.
  - 사용자가 교정하여 제시한 문장은 다듬지 말고 그대로 사용한다.
- 객관적 사실 전달에 집중한다.
- 최신 내용이나 정확한 사실 관계 파악이 필요하다고 판단되는 경우, 반드시 웹을 통해 근거를 확보하고 교차 검증을 수행한다.

## 작성자: @claude

- 태(態)
  - 행위 주체가 문장에 있거나 문맥상 자명하면 능동태로 쓴다.
    - (예) "요청은 별도의 오류 없이 무시된다" → "요청을 별도의 오류 없이 무시한다"
  - 특정 행위자가 없는 상태 서술의 피동은 허용한다.
    - (예) "라이브 스트리밍은 유지된다"
- 금지·교체 어휘
  - "이루어지다"는 쓰지 않는다. 뜻에 맞는 동작 동사로 바꾼다.
  - 지시어 "해당"은 "그"로 바꾸거나 지운다. 동사 "해당하다"(부합하다)는 무방하다.
  - 경로·도구가 실질 주어인 문장은 "~를 통해"로 처리하지 않고 주어로 승격한다.
     (예) "파이프라인을 통해 생성된 텍스트" → "파이프라인이 생성한 텍스트"
     단순한 수단 표시(예: "Client app을 통해 요청할 때")는 허용한다.
- 용어
  - 하나의 대상은 문서 전체에서 하나의 용어로 부른다. 같은 대상을 절마다 다른 어휘로 부르지 않는다.
  - 새 용어는 대변할 기존 용어가 없을 때에 한해 만들고, 최대한 이해하기 쉬운 어휘를 쓴다.
- 명사화와 조사 연쇄
  - "~했음을 …한다" 꼴은 동사문으로 푼다.
    - (예) "접수했음을 즉시 응답하고" → "접수했다는 응답을 즉시 보내고"
  - "~의"가 이어지거나 동작을 명사 속에 감춘 곳은 동사문으로 푼다.
    - (예) "PTZ 제어의 완료를 뜻하지는 않는다" → "PTZ 제어가 완료되었다는 뜻은 아니다"
  - "~와의", "~에의" 같은 겹조사는 풀어 쓴다.
- 문체 층위
  - 관용 표현과 구어체를 쓰지 않는다.
    - (예) "걸어두고", "잡히면", "훑어", "가져다 붙인다", "다룰 줄 안다", "쓸 만한지"
  - "~것"은 대체 표현이 있으면 피한다.
- 정보 밀도
  - 절차문(전체 동작 방식)은 한 단계에 한 주어의 행위만 적는다. 판정에 따른 분기는 하위 항목으로 둔다.
  - 기능 목록에는 기능만 적는다. 범위 한정의 근거는 단계별 요구사항(SRS §2.7)과 기능 요구사항(SRS §7)이 맡는다.
- 표
  - 여러 대상을 같은 축으로 대비하는 정보(국가·기업·방식 등)는 문장 대신 표로 적는다.
  - 대비에서 도출한 결론(공통점, 차별점 등)은 표 아래에 서술한다.
- 분기 표기와 라벨
  - 한 판정에 따른 상보적 분기의 나열은 "조건 → 동작" 표기를 허용한다. 이 표기는 완결 문장 규범의 예외다.
  - 행의 조건들은 서로소로 나눈다. 모든 입력이 정확히 한 행에 대응해야 한다.
  - 조건의 성립 여부는 O나 X로 표기하고, 여러 조건은 쉼표로 병기한다.
  - 기본 요소에 추가 요소가 더해지는 꼴은 +로 잇는다. (예: 액세스 토큰 + 리프레시 토큰 발급)
  - 문장의 역할을 라벨로 표시할 수 있다.
    - "주의:"는 오해를 막는 규칙의 환기
    - "근거:"는 다른 서술의 인용
